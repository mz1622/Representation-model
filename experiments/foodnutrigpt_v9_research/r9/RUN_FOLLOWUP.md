# 长训练的估时与定时回访

用户于本次研究中明确要求：先估算训练时间，安排到时唤醒或完成事件，再检查结果；不要让模型持续查看 epoch。该要求从下一项训练起执行。

1. 启动前，用同硬件、相近模型和完整既有运行的耗时估算本次成本，并记录依据、开始时间、预计结束时间和后处理余量。最近轴×数值候选 60 轮含运行内评价为 10,564.781 秒（约 2.93 小时），独立重放、比较、分析和完整训练拟合又约数分钟；相同规模的下一项可先估计训练约 3 小时，首次回访约启动后 3 小时 10 分钟。
2. 原实验控制器负责串行训练、评价、写入完成或失败状态。启动后只核对一次进程身份和配置，再通过 Codex 的线程内定时任务安排回访，保存工具返回的任务 ID 与时间。具体间隔随本项估时确定，不设按 epoch 的观察器，也不让模型反复等待一分钟再读日志。
3. 唤醒后先检查控制器/工作进程的实际身份、终止状态及产物。如果已经完成，继续独立审计、诊断、版本决定与中英文报告；如果失败，保留原产物并定位原因。观察超时、状态文件陈旧或暂时未读到输出，都不能单独成为重启训练的理由。
4. 到估计时刻仍在运行时，做一次健康检查并按剩余量重新安排回访。只有失败、需要用户动作或有实质新结果才报告；普通 epoch 变化不触发消息。仍在运行不是研究被阻塞。
5. 如果提前出现自动 Goal 续轮，而已经设置了回访、没有新的独立工作，就结束该续轮并等待计划回访，不新增查询或睡眠轮询。保持研究目标未完成状态，不把等待误记为研究成功或失败。
6. 每次回访处理后更新或停用同一个定时任务，避免重复提醒。新的实验必须先完成登记和功能核验；定时任务本身不授权跳过研究验收。

这只改变作业跟进方式，不改变任何数据、模型、损失、种子、评分或接受门槛。[官方线程内定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)支持在原任务中按计划继续长操作；[Goal 说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)说明无工具调用的续轮会抑制下一次自动续轮，避免空转。实际是否已设置回访，以保存的工具回执为准，本文不冒充调度成功回执。
