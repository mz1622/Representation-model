# 训练名称输入的尺度诊断

研究问题：在容量增大未获得明确补全收益后，同一输入的数值条件是否值得单独检验？这是训练集描述性诊断，不能由较小的初始贡献断言模型忽略文本。

仅使用64,700条训练档案的42,469个不同原始名称字符串，对既有PCA32向量按不同字符串等权拟合每坐标均值与总体标准差。完全相同字符串的缓存向量须逐项一致；验证向量、营养标签、来源权重均不用于拟合，不合并食品身份或别名。统计量SHA256 `523a5eaf9f19291fa7fd22e0661b2489b1ffd0a35ba35755a7b98d5fed0afb4f`，实际代表行指纹与缓存/数据指纹均保留。

在固定seed20260922初始化的512 MLP上，抽取8,192个真实训练家族任务，只分解第一线性层的输入贡献，无loss、优化器或模型更新；隐藏标签不参与该贡献。各坐标标准差最小/中位/最大为0.0738413/0.0947915/0.1929894，均值绝对值最大0.0204983。第一层贡献RMS如下：

| 输入块 | 原始RMS | 对同一权重仅标准化名称后 |
|---|---:|---:|
| 名称 | 0.015465 | 0.140004 |
| 可见营养值 | 0.142286 | 不变 |
| 可见性掩码 | 0.142121 | 不变 |
| 两个数值块联合 | 0.196897 | 不变 |

名称/数值联合贡献比例由0.07854变为0.71105。RMS平方含交叉项，不把各块RMS直接相加。该诊断说明内部标准化会改变初始数值平衡，不能证明这种改变会改善训练、泛化或名称检索，也没有观测训练后全部层的文本依赖。

入口 `scripts/diagnose_foodnutrigpt_name_conditioning.py`，辅助 `src/foodcomp/research_conditioning.py`，结果 `reports/v9_r2_name_conditioning_diagnostic_v1/`。诊断耗时1.45秒，记录执行时HEAD `b500022`及脚本/模块精确SHA256（新增源码在后续提交保存）。首次测试命令遗漏`PYTHONPATH=src`导致收集失败，修正调用后6项有意义的测试通过：训练唯一名称等权、验证值变为NaN仍不改变统计量、拒绝误纳验证行、同名不同向量、非有限训练输入、退化坐标。没有跳过失败测试或产生训练候选结果。

冻结名称缓存、外部learner输入、监督和指标均未改变。后续候选须在模型内部保存训练统计量、推理只加载而不重拟合，先通过默认行为兼容性和保存重载/隐藏标签验收，再启动完整训练。历史测试保持关闭。
